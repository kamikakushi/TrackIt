## 实时卡尔曼滤波器

实时卡尔曼滤波器的使用，需要引入[OnLineTrajectoryKF]类，该类将`agent_id`一样的车辆定位点视为同一条概率链，示例代码如下：

```python
# 1. 从gotrackit导入相关模块
import pandas as pd
from gotrackit.tools.kf import OnLineTrajectoryKF

# 这是一个接入实时GPS数据的示例函数，用户需要自己依据实际情况去实现他
def monitor_rt_gps(once_num: int = 2):
    gps_df = pd.read_csv(r'./gps.csv')
    num = len(gps_df)
    gps_df.reset_index(inplace=True, drop=True)
    c = 0
    while c < num:
        yield gps_df.loc[c: c + once_num - 1, :].copy()
        c += once_num

if __name__ == '__main__':

    ol_kf = OnLineTrajectoryKF()
    res = pd.DataFrame()
    for _gps_df in monitor_rt_gps(once_num=1):
        if _gps_df.empty:
            continue
        ol_kf.renew_trajectory(trajectory_df=_gps_df)
        _res = ol_kf.kf_smooth()
        res = pd.concat([res, _res])
    res.reset_index(inplace=True, drop=True)
    res.to_csv(r'./online_smooth_gps.csv', encoding='utf_8_sig', index=False)
```


## 实时匹配接口

实时地图匹配的使用，需要引入[OnLineMapMatch]类的[execute]方法，该类将`agent_id`一样的车辆定位点视为同一条概率链，示例代码如下：

```python
# 1. 从gotrackit导入相关模块
import pandas as pd
import geopandas as gpd
from gotrackit.map.Net import Net
from gotrackit.MapMatch import OnLineMapMatch
from gotrackit.tools.kf import OnLineTrajectoryKF

# 这是一个接入实时GPS数据的示例函数，用户需要自己依据实际情况去实现它
def monitor_rt_gps(once_num: int = 2):
    loc_df = pd.read_csv(r'./gps.csv')
    num = len(loc_df)
    loc_df.reset_index(inplace=True, drop=True)
    i = 0
    while i < num:
        yield loc_df.loc[i: i + once_num - 1, :].copy()
        i += once_num

if __name__ == '__main__':

    link = gpd.read_file('Link.shp')
    node = gpd.read_file('Node.shp')
    my_net = Net(link_gdf=link, node_gdf=node)
    my_net.init_net()

    # 新建一个实时匹配类别
    ol_mpm = OnLineMapMatch(net=my_net, gps_buffer=50,
                            out_fldr=r'./data/output/match_visualization/real_time/')

    # 新建一个实时卡尔曼滤波器
    ol_kf = OnLineTrajectoryKF()

    c = 0
    for rt_gps_df in monitor_rt_gps(once_num=2):
        if rt_gps_df.empty:
            continue
        ol_mpm.flag_name = rf'real_time_{c}'

        # 更新当前时刻接收到的定位数据
        ol_kf.renew_trajectory(trajectory_df=rt_gps_df)

        # 滤波平滑
        gps_df = ol_kf.kf_smooth(p_deviation=0.002)

        # 实时匹配
        res, warn_info, error_info = ol_mpm.execute(gps_df=gps_df,  overlapping_window=3)
```

## 实时地图匹配实现原理

### 核心思想

实时地图匹配与离线匹配的最大区别在于**增量处理**和**状态保持**。实时匹配需要：

1. **批次处理**：GPS数据分批到达，每批独立处理
2. **状态连续性**：保持前后批次之间的概率链连续性
3. **低延迟**：快速响应，及时输出匹配结果

### 实现架构

#### 1. 状态管理机制

`OnLineMapMatch`类维护两个关键字典来保存车辆的历史状态：

**his_hmm_dict（历史HMM对象字典）**

- 存储每个`agent_id`对应的HiddenMarkov对象
- 包含上一批次的：
    - 候选路段集合
    - 发射概率矩阵（GPS点在各路段上的概率）
    - 状态转移概率矩阵（路段间转移概率）
    - Viterbi求解器状态

**his_gps（历史GPS缓存字典）**

- 临时存储GPS点数不足的批次（≤1个点）
- 与下一批次合并后再进行匹配处理

#### 2. 重叠窗口机制（Overlapping Window）

**作用**：解决批次边界的匹配断裂问题

**原理**：

- 从上一批次的**末尾**提取`overlapping_window`个GPS点
- 将这些点作为当前批次的**起始状态**
- Viterbi算法利用这些重叠点建立概率链的连续性

**示例**：

```
批次1: [P1, P2, P3, P4, P5]          -> 匹配得到 [R1, R2, R3, R4, R5]
                overlapping_window=3
批次2:              [P3, P4, P5] + [P6, P7, P8] -> 复用P3-P5的概率，匹配P6-P8
```

#### 3. 关联判定机制

系统通过**时间阈值**和**距离阈值**判断当前批次是否与历史数据相关联：

**参数说明**：

- `time_gap_threshold`（默认1800秒）：上批次最后GPS点与当前批次第一个GPS点的时间间隔
- `dis_gap_threshold`（默认600米）：上批次最后GPS点与当前批次第一个GPS点的空间距离

**判定逻辑**：

```python
if (时间间隔 >= time_gap_threshold) OR (空间距离 >= dis_gap_threshold):
    # 认为是新轨迹，独立匹配（不使用历史概率）
    cor_with_his = False
else:
    # 认为是连续轨迹，复用历史概率
    cor_with_his = True
```

**意义**：避免车辆长时间停留或跳跃后，错误地使用旧的概率分布。

#### 4. HMM概率链维护

基于**隐马尔可夫模型(HMM)**的Viterbi算法求解最优路径：

**概率模型**：

- **发射概率** $P(观测|状态)$：GPS点在某路段上的概率
    - 考虑投影距离（点到路段的垂直距离）
    - 考虑航向角差异（GPS方向与路段方向的偏差）
  
- **转移概率** $P(状态_i → 状态_j)$：从路段i转移到路段j的概率
    - 考虑最短路径距离与GPS直线距离的差异
    - 使用`beta`参数控制对距离的敏感度

**实时匹配的特殊处理**：

当`cor_with_his=True`时，Viterbi算法的初始化使用**历史发射概率**：

```python
# 提取上批次末尾重叠点的概率分布
his_emission = self.his_hmm_dict[agent_id].extract_emission(seq_list=last_seq_list)

# 将历史概率作为初始分布传入Viterbi
hmm_obj.hmm_rt_execute(last_em_para=his_emission, last_seq_list=last_seq_list)
```

这确保了当前批次的匹配起点与上批次的匹配终点概率一致。

#### 5. 算法流程

```
┌─────────────────────────────────────────┐
│ 接收当前GPS批次                         │
└──────────────┬──────────────────────────┘
               │
               ▼
      ┌────────────────┐
      │检查his_hmm_dict│
      └─────┬────────┬─┘
        有历史│        │无历史
            │        │
   ┌────────▼───┐ ┌──▼──────────┐
   │加载HMM对象│ │检查his_gps  │
   │及参数     │ │缓存         │
   └─────┬──────┘ └──┬─────────┬┘
         │          有│         │无
         │      ┌────▼──┐  ┌───▼─────┐
         │      │合并批次│  │存储批次 │
         │      └────┬───┘  │等待下次 │
         │           │      └─────────┘
         └──────┬────┘
                │
                ▼
   ┌────────────────────────────┐
   │时间/距离阈值判定            │
   └─────┬──────────────────┬───┘
   连续轨迹│                  │新轨迹
         │                  │
┌────────▼─────┐     ┌──────▼────────┐
│提取历史概率  │     │独立匹配       │
│和重叠状态    │     │(初始概率=0)   │
└────────┬─────┘     └──────┬────────┘
         │                  │
         └────────┬─────────┘
                  │
                  ▼
   ┌──────────────────────────┐
   │生成候选路段(top-K最近)   │
   │计算转移概率矩阵          │
   │计算发射概率矩阵          │
   └──────────┬───────────────┘
              │
              ▼
   ┌──────────────────────────┐
   │Viterbi算法求解           │
   │(使用历史概率初始化)      │
   └──────────┬───────────────┘
              │
              ▼
   ┌──────────────────────────┐
   │提取匹配路径              │
   │填补路段空隙              │
   │保存发射概率供下次使用    │
   └──────────┬───────────────┘
              │
              ▼
┌─────────────────────────────┐
│输出匹配结果                 │
│更新his_hmm_dict             │
└─────────────────────────────┘
```

### 关键参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `overlapping_window` | 3 | 重叠窗口大小，建议2-5之间 |
| `time_gap_threshold` | 1800秒 | 时间间隔阈值，超过则认为新轨迹 |
| `dis_gap_threshold` | 600米 | 距离间隔阈值，超过则认为新轨迹 |
| `gps_buffer` | 200米 | GPS搜索半径，限定候选路段范围 |
| `beta` | 6.0 | 转移概率参数，越大对距离越不敏感 |
| `gps_sigma` | 30.0 | 发射概率参数，越大对投影距离越不敏感 |

### 优势与权衡

**优势**：

- ✅ **低延迟**：批次到达立即处理，无需等待完整轨迹
- ✅ **内存友好**：不需要存储完整历史轨迹，只保存必要的概率状态
- ✅ **连续性保证**：通过重叠窗口和历史概率，确保匹配路径的连续性

**权衡**：

- ⚠️ **参数敏感**：重叠窗口大小、阈值设置影响匹配质量
- ⚠️ **批次依赖**：过小的批次可能导致信息不足，匹配不准确
- ⚠️ **计算开销**：需要维护每个agent的状态，车辆数量多时占用内存

### 典型应用场景

1. **车辆实时导航**：GPS数据实时到达，需要立即反馈路径
2. **实时路况监测**：根据车辆位置实时统计道路流量
3. **异常行为检测**：实时识别车辆偏离预期路线
4. **在线轨迹可视化**：实时在地图上展示车辆运动轨迹
